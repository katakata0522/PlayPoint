# 計測優先4項目の修正と受入手順（2026-10-16）

## 範囲と反映先

日本語記事の導線分類、逆算の対象額エラー、購入確認リンクの位置、GA4診断、同条件収益比較を対象にする。計算式・記事本文・広告設定・同意方式・個人情報の収集は変更しない。他の潜在不具合は検証結果として分離し、修正を混ぜない。

WebのGitHub/Xserver反映と、スプレッドシートに紐づくApps Scriptへの導入は別工程。ソースやCIの成功をGoogle側の登録・受信成功と呼ばない。PR #599のruntime差分を含むため重複マージしない。

## 1. 記事導線

`analytics-core.js`で日本語パンくず・本文末関連記事・カテゴリ選択を既存の有限分類へ接続する。同じクリックから別種類のイベントが発生する場合があるため、記事ナビと計算機CTAを足して人数や遷移率にしない。本文中の全リンクを計測する変更ではない。URLのクエリ・アンカー・自由入力を追加送信しない。

## 2. 逆算と購入確認

逆算の`errorEligibleAmount`は`eligible_amount`へ分類する。`purchase-check`は`result_decision_link_clicked`の`link_position`だけに許可し、他イベントは従来の数値位置1〜10を維持する。同意拒否・保留後の拒否・重複送信・外部URLの除外は既存の境界を保つ。

## 3. Google側の診断

既存Apps Scriptをバックアップし、同じプロジェクトに`playpoint-measurement-review.gs`を追加する。既存のcore、p1p2、maintenanceモジュールと一緒に使い、別プロジェクトや新しいタイマーを作らない。対象ブックIDとGA4プロパティ489079798の一致を実行前に検証する。

手動実行する順序は`capturePlayPointReaderParameterAudit()`、`capturePlayPointMeasurementSettingsAudit()`。後者は`🔬計測設定・受信監査`へ出力する。Admin APIの登録一覧、Data APIの利用可能列、反映待ち3日を置いた観測回数を別々に示す。管理APIが読めなければUNAVAILABLEとし、未登録と断定しない。1項目の照会失敗で別項目を止めない。

登録済みでも値が未観測なら未使用や反映待ちの可能性がある。今回の修正後の値は、修正前の期間に出ないのが自然。必要なカスタム定義が欠けていても自動作成・再作成せず、既存定義と登録履歴を確認する。OAuthスコープを増やさない。

内部トラフィック定義とデータフィルタの状態は管理画面で別々に確認する。ACTIVE化やIP追加はこの処理では行わない。本番ネットワーク・DebugViewの確認は合成テストと区別し、既存のテスト用除外方針を確認してから最小回数で行う。広告をクリックしない。実注文番号・メール・入力金額・トークン・生のリクエストURLを証跡へ保存しない。

受入は、同意ありの対象操作1回に対応するイベント・分類が正しいこと、同意拒否では送信されないこと、後日の日次診断で対象値が観測されること。CIで外部通信を止めた成功は、Google側の受信成功の代用にしない。

## 4. PC収益の同条件比較

手動で`capturePlayPointRevenueLikeForLike()`を実行し、`⚖同条件収益比較`を読む。標準は3日反映待ちの完了7日と、その前の非重複7日。関数内の期間生成は7・14・28日を扱えるが、未来や反映待ちの終了日は拒否する。

GA4から端末×国×ページを同時に取得し、前期間に占めた各組み合わせのPV比率を固定して比較する。国別とページ別の別表を掛け合わせない。両期間にPVのある共通組だけを構成補正し、新規・消失・未設定は別に扱う。元の全体実績、共通組の閲覧カバー率、構成を固定した差、共通組内の構成差を残す。

指標はGA4のscreenPageViews、publisherAdImpressions、totalAdRevenue。通貨JPYとAsia/Tokyoを応答でも確認する。AdSense画面のページRPMと同一指標ではない。人数やセッションを行合計しない。欠測・重複・不正数値・取得途中の件数変化・過大レポートは停止。しきい値、サンプリング、収益閲覧制限があれば構成補正しない。ゼロ分母は空欄にする。

新規ページや少数PVが多い場合は補正可能な範囲が狭くなるため、カバー率を先に読む。9/19の計測復旧、10/2〜8の旧広告実験、10/9の移行などの影響は残る。補正値を広告変更の因果効果や有意差とは扱わない。取得失敗時に前回の正常結果を0で上書きせず、同名の別用途シートや新しい取得結果も上書きしない。

## 公開前後の検証

最初に未共有作業と現在のブランチを確認する。対象PRのソースに対して`node scripts/prepare-pr.cjs`を実行し、公開資産の参照ハッシュを同期する。変更日時・アセット版は既存の固定値を使う。本文や広告変更が混ざっていないことを確認して生成物を同じブランチへコミットする。必須PR Gateが現在のHEADで成功する前にマージしない。

関連テストは`tests/article-navigation-observability.test.cjs`と`tests/playpoint-revenue-integrity.test.cjs`へ統合。全体は`node .github/scripts/preflight.cjs`、ブラウザは既存PR Gateを使う。既存の分類台帳や検査基準を緩めない。本番反映後は配信リビジョン・JS・主要画面を確認し、その後にGoogle側の受入を行う。

参考: Google Analytics Admin API customDimensions.list、Data API RunReportResponse / ResponseMetaData。読み取り不能と未登録・未使用を分離し、API応答の行数・列・取得制限も判定に含める。
