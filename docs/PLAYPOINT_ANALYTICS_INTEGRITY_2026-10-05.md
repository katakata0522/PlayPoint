# PlayPoint Analytics 全体確認・修正記録

対象は既存のPlayPoint Analyticsに紐づくApps Script。本体・GSC 28日比較・P1/P2分析・実シート・7本の既存トリガーを照合した。個人アカウント情報、分析実数、稼働本体の全文はリポジトリへ保存しない。Drive修復の次の改善単位としてv11.6.3を稼働プロジェクトへ保存した。

## 確認できた問題と対処

| 問題 | 対処 |
| --- | --- |
| 当日速報の保存後に未定義の`provisionalState`を参照し、トリガーが失敗する | 取得成否からPROVISIONAL/NO_ROW/PARTIALを算出。本体の旧版で例外を再現した |
| 日次APIのNO_ROWで保存済みのPV・収益を0へ上書きする | ソースごとに既存値を保持し、新規未取得値は空欄にする。日次状態もPARTIALとする |
| 30日内の回復対象が「行そのものがない日」に限定される | NO_ROWを含む日も再取得対象へ戻す |
| 空欄の再読込・移動平均で未取得を0へ変換する | nullを保持し、移動平均・曜日平均の分母から未取得日を除外する |
| 月間ユーザーの未取得を0とし、部分的な月を正常集計に見せる | 未取得ユーザーを空欄にし、月次に未再照合日数・状態を追加する |
| シートの全消去後に書き込むため、書込エラーで既存出力が消える | 列数・必要サイズを先に検証し、一括書込後に余った末尾だけ消去する |
| 定期更新ごとに全列の自動幅調整を繰り返す | 初回のみ自動調整し、既存の明示的な列幅を維持する |
| GitHub管理版の追加スクリプト修正が稼働版へ未反映 | 共通期間、未取得/0の区別、検索クロスの総件数・表示件数・PARTIAL、計算指標の意味、設定再利用、トリガー導入時の日本時間・失敗巻戻しを揃える |
| GA4 P1取得がlimitで切れても正常扱い | rowCountまでoffsetで取得。途中の空応答・行数変動・100,000行超は未取得として扱う |
| 全ソース失敗時に空の分析結果で前回結果を置換する | 全ソースの取得失敗では書込前に停止し、監視にERRORを残す |
| 追加分析と本体が同時に監視行・履歴を更新できる | 本体のスクリプトロックをGSC、P1/P2の各段階、収益診断でも共有する |
| 追加スクリプトに429/5xxの限定再試行がない | 本体の通信関数を共有。単体利用でも3回まで再試行。403などは再試行しない |
| Drive補助保存失敗が実行ログだけ、GSC 28日収集の監視行がない | それぞれ独立した監視行を追加。日次正常保存とDrive失敗を分離したまま可視化する |
| P1/P2の古いOK・停止したRUNNINGが残る | 週次分析9日、収益診断36時間、RUNNING45分を超えた場合はSTALEを表示する |
| GSC検索語明細を全検索データと誤解できる | APIで取得可能な上位行であることを比較シートに明示し、Property Totalを総量の参照先とする |
| 存在しない日付でもGSC比較期間が作れる | ISO日付の実在性を検証する |
| 検索語の先頭`=`をSheetsの数式として解釈できる | 外部の検索語・文字列を文字列として保存する |
| 収益異常分析が調査時点の値で停止し、管理コードが稼働プロジェクトにない | 診断モジュールを導入し、既存の日次同期内に接続する。専用トリガーは追加しない |
| 収益診断の「28日」が欠損時にそれより古い日まで広がる | 直前28暦日のRECONCILED行に限定し、14日未満はINSUFFICIENT_HISTORYとする |
| 記事Portfolioが9月25日の判断用資料のまま、自動更新対象と混同できる | 監視に資料日時とSTALEを表示。役割・編集優先順位の手動判断は上書きしない |

## 正常と確認したもの・設計上の限界

- SEO改善候補は`QUERY`数式で最新の検索語×ページを参照している。別の重複更新処理は追加しない。
- GSCのRaw、fragmentだけを除くNormalized、Property Total、隣接した非重複28日窓は維持する。
- GA4とGSCの「同じ日付範囲」は日付ラベルの統一。GA4の日本時間とGSCのPacific時間の24時間が完全一致する意味ではない。
- Success users / Start usersは期間内の人数比であり、同一コホートを追った遷移率ではない。全流入広告収益 / Organic LPユーザーも自然検索だけの収益単価ではない。稼働版の見出しを管理版の説明へ揃える。
- GA4のしきい値・サンプリング等、GSCの匿名検索・内部上限はAPI上の制約。ページ送りはAPIが公開する結果を取得する保証であり、全実ユーザーや全検索語の保証ではない。
- 保存済み398日中、359日は旧「GA4・AdSense取得済み」表記、39日はRECONCILED表記だった。履歴の表記を再取得なしに確定済みへ書き換えない。
- ページ日次の365日背景補完は継続中。今回の日次同期で2026-03-05～03-18の補完が成功した。全365日が完了したとは報告しない。
- 記事Portfolioの最新化は、現行記事台帳、編集履歴、検索意図、役割・優先順位の基準を合わせる別の更新単位。監視のSTALE表示を資料の更新完了と扱わない。
