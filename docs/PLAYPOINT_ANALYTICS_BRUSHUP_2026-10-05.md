# Analytics 更新処理の追加改善（2026-10-05）

前回の取得・保存修復に続き、誤った評価表示、入力の不整合、更新同士の競合と失敗時の上書きを修正した。

| 問題 | 改善 |
| --- | --- |
| 未計測の暫定記事が PROVE と表示され、需要不足の判断に見える | UNASSESSED を使用。人間が判断した既存分類は保持 |
| 保持した行数が確認済み編集判断数に見える | 保持行数と判断日時がある件数を別表示。ログも同じ意味へ統一 |
| P1 と台帳の対応状況が分かりにくい | OK / PARTIAL / NO_MATCH の件数を表示。未取得は空欄を維持 |
| 台帳にはない日本語検索索引記事を見逃す | 双方向照合し、矛盾時は旧 Portfolio を保持 |
| 不正な役割名・パスが入力できる | 自身の定義にある役割だけ許可。不正パスを拒否 |
| 実在しない日付、未来、30日以外の P1 期間を受理 | 実在する過去30日・既存鮮度条件を検証 |
| 壊れた再開位置や日付だけの履歴を取得済みと扱う | 365日の期間・カーソル・API応答・行数・確認日時を照合。欠落時は同じ期間を再検証 |
| Sheets の書込確定前に取得カーソルが進む | flush 成功後だけカーソルを保存 |
| 長い URL 検査が共通ロックを占有する | 通信中はロックを解放。表・健康状態の書込だけ短くロックし、同じ検査は期限付きリースで重複防止 |
| 全対象取得失敗でも検査表を置換し PARTIAL 成功と扱う | 全件失敗・空対象は ERROR として旧表を保持。不完全API応答も失敗として扱う |
| 概要の説明が細い分類列で折り返され、固定領域が画面を占有する | 生成する概要領域だけ横幅を確保し、行高を再調整。記事行の分類・メモは保持 |

## 残る改善候補

役割固有KPI（再訪・解決・文脈別の次行動）は未計測のままであり、補助指標から成功を断定しない。計測を追加する際は読者の操作と同意条件を先に定義する。検索クロス分析の表示上限によるPARTIALは取得エラーではなく、必要な切り口の閲覧を今後の改善候補とする。

URL Inspection は Google が保持するインデックス版を返すため、公開ページの現時点のクロール可否とは別に確認する。[公式API](https://developers.google.com/webmaster-tools/v1/urlInspection.index/inspect)。リースは通常実行上限を超える7分で期限切れにする。[Apps Script の実行上限](https://developers.google.com/apps-script/guides/services/quotas)。

全ソースの退避、分析値、照合証拠は非公開のローカル出力に保持し、リポジトリには公開可能な補助コード・テスト・手順だけを含める。
