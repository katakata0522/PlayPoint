# ゲーム記事一覧サムネイル運用方針

## 目的

記事一覧で「どのゲームの記事か」をタイトルを読む前に識別できるようにする。装飾のために画像を増やすのではなく、一覧の探索速度を上げるために使う。

## 表示ルール

- 通常のゲーム記事: 原則として公式アプリのゲームアイコンを小サムネイルに使う。
- 周年・大型イベント・特定コラボ: 記事内容を直接表す公式キービジュアルがあり、利用条件・出典を確認できた場合だけ個別に上書きできる。
- 記事ページ冒頭: 大きなサムネイルを標準表示しない。タイトル、更新日・公式確認日、主回答を優先する。
- OGP: 記事一覧サムネイルとは別管理とする。SNS共有用画像を一覧表示の都合で流用しない。
- 適切な公式素材が確認できない場合: 無理に画像を拾わず、既存の汎用画像へフォールバックする。

## 画像の扱い

- 公式サイト、公式ストア掲載、公式プレス・メディア素材を優先する。
- 二次転載サイト、出所不明画像、ファンアートを正本にしない。
- 加工は原則としてリサイズ、形式変換、表示枠への contain/cover 指定まで。内容を書き換えない。
- アプリアイコンは原則 contain。主要部分を切り落とすトリミングをしない。
- イベントキービジュアルは必要な範囲で cover を許可するが、主題が欠ける場合は使わない。
- 外部CDNを本番表示で直接ホットリンクしない。確認した画像はサイト内へ保存してから有効化する。

## 台帳

`scripts/game-thumbnail-assets.cjs` を通常ゲームアイコンの正本とする。

各画像で gameId / gameTitle / assetType / sourcePageUrl / sourceImageUrl / rightsHolder / acquiredAt / localPath / modification / usage / status / notes を追跡する。

`status: active` にできるのは、出典ページとローカル実体を確認し、台帳に記録した画像だけ。

## クレジット・問い合わせ対応

公式URLを記事の参考情報として示すことは、画像利用許諾を意味しない。権利者から差し替え・削除依頼があった場合に、台帳から対象ファイルと利用記事を追跡して速やかに停止できる構成を維持する。
